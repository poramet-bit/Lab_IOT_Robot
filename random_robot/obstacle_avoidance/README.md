# หุ่นยนต์หลบสิ่งกีดขวาง — UNO R4 WiFi แบบจับเวลา

เปิด `obstacle_avoidance.ino` ใน Arduino IDE เลือก **Arduino UNO R4 WiFi** และติดตั้งไลบรารี **ArduinoBLE** กับ **Servo** แล้วอัปโหลด สเก็ตช์ใหม่แยกจาก `dice_movement` และตามเส้นเดิม

ใช้สนาม 3×3 เมตร เริ่มขวาบน ช่องออกกว้าง 1 เมตรอยู่ผนังล่างฝั่งซ้าย รถเลือกทางบนหรือทางลงขวาจากระยะที่สแกนได้ แล้วตรวจสิ่งกีดขวางระหว่างเดินต่อ ใช้ PWM เต็ม 255 ทุกโหมดการเคลื่อนที่ตามคำขอล่าสุด โดยอิงระดับ PWM สูงสุดและ RIGHT_TRIM จาก `IOT-Robot/Robot/robotline_fullspeed`

**เวอร์ชันปัจจุบันไม่ใช้ encoder** ใช้เวลาสั่งมอเตอร์กับ ultrasonic/IR ขา D3 และ D11 ว่าง ไม่มีการอ่านพัลส์, ปรับสมดุลจากพัลส์ หรือเงื่อนไข `ENCODER_STALL`

## ขาและทิศมอเตอร์

| อุปกรณ์ | ขา |
|---|---|
| มอเตอร์ซ้ายจริง PWM / A / B | D5 / D6 / D7 |
| มอเตอร์ขวาจริง PWM / A / B | D10 / D9 / D8 |
| HC-SR04 ECHO / TRIG | A0 / A1 |
| Servo หมุน ultrasonic | A2 |
| IR หน้าซ้าย — OUT | A3 |
| IR หน้าขวา — OUT | A4 |
| IR หลังซ้าย — OUT | A5 |
| IR หลังขวา (ตัวที่ 4) — OUT | D2 |

ตำแหน่งเมื่อมองจากด้านบน ติด IR เยื้องซ้าย/ขวาของทั้งหัวและท้ายรถ โดยหันออกไปทางมุมแต่ละด้าน:

```text
             หัวรถ / ultrasonic
        A3 ↖                 ↗ A4
           ┌───────────────┐
           │      รถ       │
           └───────────────┘
        A5 ↙                 ↘ D2
                   ท้ายรถ
```

เดินหน้าของแต่ละมอเตอร์คือ A=LOW, B=HIGH; ถอยคือ A=HIGH, B=LOW; เบรกคือ A=B=HIGH และ PWM=255 ใช้ PWM 8 บิต และชดเชยล้อขวาด้วย `RIGHT_TRIM=46800/55500` ทั้งเดินและหมุน ค่า PWM ในรายงานเป็นค่าหลังชดเชยและมีเครื่องหมายลบเมื่อถอย ตอนเดินตรงเต็มได้ซ้าย 255 / ขวา 215 และปรับต่างกันเมื่อ IR สั่งแก้ทิศ

IR ตั้งต้นว่าเจอวัตถุเมื่อ LOW; ในรายงาน `IR_*=1` แปลว่าตรวจพบ ไม่ใช่ค่าดิบของขา Servo ตั้ง 180°=ซ้าย, 90°=หน้า, 0°=ขวา ปรับช่วงได้ใน `Settings.h` ให้ตรงกับกลไกจริง ใช้กราวด์ร่วมสำหรับวงจรควบคุม เซนเซอร์ และวงจรจ่ายไฟมอเตอร์/servo

รายงาน `v` แยก `IR_FL`=หน้าซ้าย, `IR_FR`=หน้าขวา, `IR_BL`=หลังซ้าย และ `IR_BR`=หลังขวา เดินหน้าจะใช้คู่หน้าเบี่ยงหนีด้านที่พบวัตถุ และเบรกพักเมื่อพบทั้งสองตัว การถอยทุกแบบตรวจคู่หลัง: ตัวใดตัวหนึ่งพบวัตถุจะหยุดถอย การหมุนอยู่กับที่ต้องให้ IR ทั้ง 4 ตัวว่าง ระหว่างสแกนเลือกทางและตามขอบ ใช้คู่หน้า–หลังฝั่งเดียวกันร่วมกัน จึงยังไม่นับว่าพ้นขอบถ้าตัวหลังยังพบวัตถุ

## คำสั่ง

เชื่อม BLE ชื่อ **OBSTACLE-ROBOT** ใช้ Nordic UART service (UUID ลงท้าย `0001`), เขียน RX (`0002`) และ subscribe TX (`0003`):

- Service: `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`
- RX: `6E400002-B5A3-F393-E0A9-E50E24DCCA9E`
- TX: `6E400003-B5A3-F393-E0A9-E50E24DCCA9E`

หรือใช้ USB Serial Monitor 115200 baud คำสั่งเหมือนกัน ไม่ต้องมี newline

| คำสั่ง | การทำงาน |
|---|---|
| `1`–`6` | `scenario(int scen)` เลือกลูกเต๋าขณะหยุด ยังไม่เคลื่อนรถ |
| `f` | เริ่มที่ขวาบน หัวรถ 0° ทุก scenario แล้วสแกนเลือกทางทันที; ส่งซ้ำระหว่างทำงานไม่มีผล |
| `s` | เบรกทันที ยกเลิกงานค้าง ต้องส่ง `f` จึงเริ่มใหม่ |
| `v` | รายงานสถานะ, PWM, เวลาหมุน, IR, ระยะเซนเซอร์ และพิกัดประมาณจากเวลา |
| `l` / `r` | ขณะหยุด ทดสอบหมุนซ้าย/ขวาครั้งละ 90° ด้วยล้อสวนทาง |
| `ml` / `mr` | ขณะหยุด ทดสอบมอเตอร์ซ้าย/ขวา 200 ms ที่ PWM 255 ก่อน trim; **ยกล้อก่อนใช้** |

ตัวอย่าง: วางรถที่ขวาบน **หัวชี้ขึ้นสนาม 0° ทุกครั้ง** → ส่ง `2` → ส่ง `f` → รถเบรกค้างขณะ servo สแกนซ้าย/หน้า/ขวา แล้วเริ่มเส้นทางที่เลือก → ส่ง `s` เพื่อหยุด ไม่มีการหมุนตั้งต้นตามเลขลูกเต๋า คำสั่ง `f` เป็นการเริ่มสนามใหม่ ไม่ใช่ resume กลางทาง จึงต้องวางกลับจุดเริ่มก่อนเริ่มใหม่ การหลุด BLE จะเบรกและไม่เริ่มเองเมื่อเชื่อมกลับ

`l/r` ต้องมี ultrasonic หน้าอ่านได้และ IR รอบตัวไม่พบวัตถุ ส่วน `ml/mr` เป็นการตรวจสายเมื่อยกล้อ ไม่ตรวจระยะก่อนหมุนล้อ

## เส้นทางและการหลบ

เมื่อส่ง `f` ทุก scenario เริ่มจากหัว 0° ที่มุมขวาบน แล้วเข้า `SCAN_ROUTE` ทันที มอเตอร์ยังเบรกระหว่างสแกน การเลี้ยวครั้งแรกเกิดหลังเลือกเส้นทางแล้วเท่านั้น เลี้ยวซ้าย/ขวาแต่ละครั้งยังเป็น 90° เทียบกับหัวรถปัจจุบัน

ในโค้ดเดิมเลขลูกเต๋าแตกต่างกันเฉพาะมุมเริ่ม เมื่อใช้หัว 0° ร่วมกัน ลำดับเส้นทางจึงเหมือนกันทุกเลขสำหรับข้อมูลเซนเซอร์เดียวกัน คำสั่ง `1`–`6` ยังใช้เลือก scenario และรายงาน `SCEN` ตามเดิม แต่ไม่ได้สั่งหมุนตั้งต้นหรือบังคับเลือกทางบน/ล่าง

| Scenario | ทางบน: ขวาบน→ซ้ายบน→ออก | ทางล่าง: ขวาบน→ขวาล่าง→ซ้ายล่าง→ออก |
|---|---|---|
| 1–6, หัวเริ่ม 0° | ซ้าย → ตรง → ซ้าย → ตรงออก | ถอย → ซ้าย → ตรง → ซ้าย → ตรงออก |

การเลือกใช้ระยะโล่งที่วัดได้ (คิดคะแนนถึง 150 ซม.) หักค่าเลี้ยว และให้ทางถอยที่มองด้วย ultrasonic ไม่ถึงมีลำดับต่ำกว่า เมื่อคะแนนเท่ากันเลือกทางบน นี่เป็นการเลือกจากข้อมูลเฉพาะที่ ไม่ได้รู้ว่าสิ่งกีดขวางทั้งสองอยู่ตรงไหนและไม่ได้รับรองเส้นทางเร็วที่สุดทั้งสนาม

ใช้เวลาที่สั่งมอเตอร์และอัตราเร็วที่ตั้งไว้ประมาณพิกัดจากจุดเริ่มที่ขอบรถห่างผนังบน/ขวาประมาณ 40 ซม. ตรวจผนังร่วมกับพิกัดที่คาดไว้ และหยุดช่วงเดินเมื่อถึงแนวเผื่อเลี้ยว (ศูนย์กลางรถประมาณ 35 ซม. จากผนัง) ได้ก่อนเซนเซอร์พบผนัง หากถอยแล้ว IR หลังพบผนัง จะเบรก เดินหน้าตามเวลาประมาณ 12 ซม. จน IR หลังพ้น แล้วจึงเลี้ยว ถ้าเดินหน้าไม่ได้หรือ IR ไม่พ้นใน 40 ซม. จะหยุดแจ้งเหตุ

เมื่อหน้าถูกขวางก่อนถึงผนังปลายทาง:

1. เบรกและสแกนซ้าย/หน้า/ขวา เลือกฝั่งที่มีระยะและไม่ชี้เข้าผนังใกล้ตัวตามพิกัดประมาณ
2. เลี้ยวออกข้าง เดินตามขอบด้วย IR คู่หน้า–หลังฝั่งตรงข้ามกับที่เลี้ยว
3. ต้องเคยพบขอบ แล้ว IR ทั้งคู่ของฝั่งนั้นพ้นขอบต่อเนื่องอย่างน้อย 150 ms พร้อมเดินเพิ่มอีก **ประมาณ 35 ซม. จากเวลา** และ ultrasonic หน้าโล่ง จึงเลี้ยวกลับไปทิศเดิม
4. เดินขนานสิ่งกีดขวางด้วยเงื่อนไขพบ/พ้นขอบเดียวกัน แล้วเลี้ยวกลับเข้าแนวเดินเดิมตามระยะออกข้างที่ประมาณจากเวลา
5. ถ้าฝั่งอ้อมตันหรือกลับเข้าแนวไม่ได้ จะเข้าสู่การลองใหม่ด้านล่าง หากยังแก้ไม่ได้ภายในจำนวนครั้งที่กำหนด หรือมองไม่พบขอบใน 140 ซม. จะเบรกแจ้งเหตุ

แนวออกตั้งศูนย์กลางรถที่ x≈35 ซม. จากผนังซ้าย อยู่ฝั่งซ้ายของช่องออกกว้าง 1 เมตร เมื่อพิกัดประมาณแสดงว่าพ้นทั้งคันจะเข้า `EXIT_CONTINUE` และเดินต่อ ไม่มีหยุดเพียงเพราะจบเส้นทาง แต่ยังหยุดเมื่อสั่ง `s`, BLE หลุด, พบทางตัน หรือเซนเซอร์ผิดปกติ

## การลองใหม่เมื่อทางไม่โล่ง

- `NO_START_CLEARANCE` / `NO_DETOUR_CLEARANCE`: ครั้งแรกพัก 500 ms แล้วสแกนใหม่ ถ้ายังไม่โล่งและ IR หลังว่าง จะถอยตามเวลาประมาณ 8 ซม. (สูงสุด 1.5 วินาที) แล้วเบรกและสแกนใหม่ หาก IR หลังพบวัตถุจะหยุดถอยทันที
- `TURN_CLEARANCE`, ทางอ้อม/ทางกลับถูกขวาง หรือ IR สองข้างพบวัตถุ: เบรกพักและตรวจใหม่ก่อนทำช่วงเดิมต่อ เก็บเวลาหมุนที่ทำไปแล้วและหมุนเฉพาะเวลาที่เหลือ ไม่นับช่วงรอเซนเซอร์/เบรกเป็นเวลาหมุน
- จำกัดการลองเรื่อง clearance รวม 3 ครั้งต่อการเริ่มงาน ถ้ายังไม่ผ่านจะเป็น `FAULT` พร้อมเหตุผลเดิม; เซนเซอร์อ่านไม่ได้ต่อเนื่องและ timeout ยังหยุดตามเดิม
- `s` และ BLE หลุดยกเลิกทั้งการเดินและการลองใหม่ที่รออยู่ ต้องเริ่มด้วย `f` จากจุดวางหัว 0° ใหม่

ไม่มีการตรวจล้อติดจากพัลส์แล้ว หากล้อไม่หมุนจริงแต่ยังสั่ง PWM ตัวคำนวณเวลาก็จะเดินต่อและพิกัดประมาณจะคลาดเคลื่อน

## ค่าที่ต้องจูนกับรถ

แก้ที่ `Settings.h`:

| ค่า | ค่าเริ่ม |
|---|---|
| RUN / SLOW / REVERSE / TURN PWM ก่อน trim | 255 / 255 / 255 / 255 |
| จำกัด PWM คำสั่ง | 255 |
| ขนาดกรอบรถ | 17×30 ซม. |
| หยุดหน้า / ระยะเลือก SLOW_PWM | 20 / 50 ซม. — ตอนนี้ SLOW_PWM=255 เท่ากับ RUN_PWM |
| ระยะหน้าอย่างต่ำระหว่างหมุน | 8 ซม. — ไม่ใช่ระยะรับรองพื้นที่กวาดทั้งคัน |
| ระยะสแกนเลือกทางด้านข้างอย่างต่ำ | 35 ซม. |
| TURN_LEFT_90_MS / TURN_RIGHT_90_MS | 390 / 390 ms — ค่าปัจจุบันในไฟล์ ต้องตรวจมุมกับรถจริง |
| FORWARD_CM_PER_SEC / REVERSE_CM_PER_SEC | ประมาณ 54.64 / 45 ซม./วินาที — ขยายค่าเดิมตามสัดส่วน PWM ยังไม่ได้วัดจริง |
| BRAKE_MS | 150 ms |
| MAX_CLEARANCE_RETRIES | 3 ครั้งต่อการเริ่มงาน |
| SIDE_CORRECTION_PWM | 10 — ลด PWM ล้อด้านในเมื่อ IR หน้าฝั่งใดฝั่งหนึ่งพบวัตถุ ปรับได้ใน Settings.h |
| RETRY_PAUSE_MS / RECOVERY_BACKOFF_CM | 500 ms / 8 ซม. |

ตรวจตามลำดับ:

1. ยกล้อ ส่ง `ml` / `mr` ตรวจว่าหมุนมอเตอร์ซ้าย/ขวาจริงและเดินหน้าถูกทิศ
2. วางพื้นโล่ง ส่ง `l` / `r` วัดมุมจริง ปรับเวลาแยกฝั่งด้วย `เวลาใหม่ = เวลาเดิม × 90 / มุมที่วัดได้` แล้วทดสอบซ้ำ เช่น ขวา 1500 ms หมุนได้ 120° ให้ลอง `TURN_RIGHT_90_MS=1125` ค่า 1500 ms ไม่ได้รับรองว่าจะได้ 90° ก่อนจูน และต้องจูนใหม่หากเปลี่ยน TURN_PWM หรือ RIGHT_TRIM
3. นำวัตถุเข้าหา IR ทีละตัวแล้วส่ง `v` ตรวจว่าค่า `IR_FL/FR/BL/BR` ตรงตำแหน่งจริง รวมถึง D2 ต้องขึ้น `IR_BR=1` ปรับแนวติดตั้งและ VR ให้เห็นขอบสิ่งกีดขวางได้ตามระยะอ้อมจริง การไม่เห็นขอบจะหยุด `EDGE_NOT_FOUND`
4. วัดอัตราเร็วเดินหน้าที่ RUN_PWM และถอยที่ REVERSE_PWM บนพื้นจริง แก้ `FORWARD_CM_PER_SEC` / `REVERSE_CM_PER_SEC` ค่าระยะเผื่อเลี้ยว ระยะอ้อม และพิกัดทั้งหมดใช้สองค่านี้กับเวลาสั่งมอเตอร์ ที่ PWM อื่นจะประมาณอัตราเร็วตามสัดส่วน PWM จึงยังมีความคลาดเคลื่อน
5. ทดสอบ scenario ด้วยค่าปัจจุบัน ตรวจระยะเบรกจริง แนวเดินตรง และแนวออกตามสนามจริง ตอนเดินตรงชดเชยล้อด้วย RIGHT_TRIM และหลบด้านข้างจาก IR เท่านั้น

## รายงานและข้อจำกัดของการวัด

`CONTROL=TIMED` ระบุโหมดจับเวลา; `TURN_90_MS_L/R` แสดงเวลาจูนซ้าย/ขวา; `HEAD` คือหัวที่คาดไว้หลังหมุนครบเวลา ไม่ใช่มุมวัดจริง; `EST_X_CM/EST_Y_CM` เป็นพิกัดประมาณจากเวลาและ PWM ไม่มีข้อมูลวัดการเคลื่อนที่ของล้อ

`LAST_ISSUE` และ `CLEARANCE_RETRIES` แสดงเหตุที่ลองใหม่; `FRONT_CM=-1` คืออ่านไม่ได้ ส่วน `SCAN_L/R_CM` เป็นผลสแกนครั้งล่าสุด ไม่ใช่ค่าด้านข้างสดระหว่างเดิน รายงานส่งเมื่อเปลี่ยนสถานะและเมื่อสั่ง `v`; ข้อมูลใหม่แทนข้อมูลเก่าที่ยังส่งไม่จบได้

A0 ของ core UNO R4 ไม่มี external interrupt จึงใช้ `pulseIn` จำกัดรอ echo 26 ms แล้วรับคำสั่งหยุดอีกครั้งก่อนสั่งมอเตอร์ ไม่ใช้ `delay()` รอ servo/การเดิน การสแกนใช้ 3 ครั้งต่อมุม ต้องอ่านได้อย่างน้อย 2 ครั้งและเลือกระยะใกล้สุด

ไม่มี echo ติดต่อกัน 3 ครั้งจะรายงาน `FRONT_STATUS=NO_ECHO` และใช้พฤติกรรมเดินหน้าต่อของโค้ดปัจจุบัน โดยยังตรวจ IR และคำสั่งหยุด ค่านี้ไม่ใช่ระยะที่วัดได้ และไม่สามารถแยกพื้นที่ไม่มีผิวสะท้อนออกจากเซนเซอร์ที่ไม่ส่ง echo ได้ ส่วนข้อมูลเก่า/echo นอกช่วงที่ยังไม่ยืนยัน `NO_ECHO` จะเบรก และ fault เมื่ออ่านไม่ได้ต่อเนื่อง 1.5 วินาที

ลำ ultrasonic กับ IR ดิจิทัลยืนยันช่องผ่านทั้งคันไม่ได้; การลื่นไถล ความเร็วเปลี่ยนตามแบตเตอรี่/พื้น และเวลาหมุนที่จูนคลาดเคลื่อน เซนเซอร์ติดตั้งไม่ตรงตำแหน่ง และรูปร่างสิ่งกีดขวางมีผลต่อเส้นทางนี้ การอ้อมเป็นแบบมีขอบเขตและหยุดเมื่อข้อมูลไม่พอ ไม่ใช่ระบบทำแผนที่หรือหาทางออกได้ทุกการจัดวาง ขอบเขตโบนัสยังไม่ทราบ จึงตั้งแนวออกฝั่งซ้ายโดยไม่อ้างว่าได้คะแนนแน่นอน

## ตรวจซอฟต์แวร์

```sh
# รันจากโฟลเดอร์ random_robot
obstacle_test_dir=$(mktemp -d /tmp/obstacle-tests.XXXXXX)
g++ -std=c++11 -Wall -Wextra -Werror -pedantic obstacle_avoidance/tests/navigation_tests.cpp -o "$obstacle_test_dir/navigation_tests"
"$obstacle_test_dir/navigation_tests"
g++ -std=c++11 -Wall -Wextra -Werror -pedantic -Iobstacle_avoidance/tests/stubs obstacle_avoidance/tests/sketch_tests.cpp -o "$obstacle_test_dir/sketch_tests"
"$obstacle_test_dir/sketch_tests"
arduino-cli compile --fqbn arduino:renesas_uno:unor4wifi obstacle_avoidance
```

ทดสอบบน host: เดินและหมุนได้โดยไม่มีข้อมูลล้อ, D3/D11 ไม่ถูกตั้งค่า, เริ่มหัว 0° และสแกนโดยไม่หมุนตั้งต้นครบทั้ง 6 scenario, หมุนซ้าย/ขวาตามเวลาและไม่นับช่วงพัก, IR ทั้ง 4 ขา/รายงานแยกมุม/หยุดหมุน, คู่หลังหยุดถอยและถอยแก้ทาง, พ้นขอบทั้งหัวและท้ายก่อนเลี้ยวกลับ, ขีดจำกัดการลองใหม่, ทั้งสองเส้นทางครบทุก scenario, stop ทุกสถานะ, timeout/clock wrap, เซนเซอร์หาย, BLE/USB/ขามอเตอร์/เบรก และหยุดแล้วเริ่มสแกนใหม่ ทดสอบด้วยแบบจำลอง ไม่ได้แทนการวิ่งบนรถจริง
