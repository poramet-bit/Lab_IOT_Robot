# สรุปเซสชัน: Line Following Robot (PD Controller)

วันที่: 2026-09-14
ไฟล์ที่เกี่ยวข้อง:
- `robot_line_following_PD_plan.md` (แผนงานตั้งต้น)
- `robot_line_following_PD/robot_line_following_PD.ino` (โค้ดที่สร้างและแก้ตามเซสชันนี้)

## 1. สร้างโค้ดจากแผนงาน

สร้าง `robot_line_following_PD.ino` ตามโครงสร้างในแผน (`Position()`, `PD()`, `motors()`) พร้อมรวมค่าที่ปรับแต่งได้ (pins, sensor logic, weights, PD constants, PWM range) ไว้เป็นบล็อก CONFIG เดียวที่ต้นไฟล์ และเพิ่มโหมดทดสอบ (`TEST_MODE` 0-3) ให้ตรงกับขั้นตอนทดสอบในแผนข้อ 8 (ทดสอบเซนเซอร์ / Position / มอเตอร์ / วิ่งจริง)

## 2. ทำความเร็วสูงขึ้นแต่ยังจับเส้นทัน

จุดที่ต้องปรับ:
1. **Kd สูงกว่า Kp เมื่อเพิ่มความเร็ว** — หน่วงการส่ายตอน error เปลี่ยนไว
2. **เพิ่ม BaseSpeed ทีละน้อย** — ต้อง re-tune Kp/Kd ใหม่ทุกครั้งที่เพิ่มความเร็ว
3. **ระยะเซนเซอร์ยื่นหน้ารถ (look-ahead)** — สำคัญที่สุด เป็นจุดกลไก ไม่ใช่โค้ด ต้องยื่นไกลขึ้นเมื่อรถวิ่งเร็วขึ้น เพื่อเห็นโค้งล่วงหน้าทัน
4. **ลดความเร็วอัตโนมัติตอนเข้าโค้ง (curve slowdown)** — ทำแล้วในโค้ด (ดูข้อ 3)
5. ไม่มี `delay()` บล็อกใน loop จริงอยู่แล้ว
6. ปรับความละเอียด `WEIGHTS`/`SETPOINT` ให้ตอบสนองไวขึ้น

## 3. เพิ่มฟีเจอร์ Curve Slowdown

เพิ่ม config: `CURVE_SLOWDOWN_ENABLE`, `MIN_CURVE_SPEED`, `MAX_ERROR_FOR_SCALE`

หลักการ: `|error|` มาก (โค้งแรง) → ลด `effectiveBaseSpeed` ลงอัตโนมัติ (map จาก `baseSpeed` ไปหา `MIN_CURVE_SPEED`) ทางตรงยังวิ่งเต็มความเร็ว โค้งชะลอเอง ทำให้เพิ่ม `BaseSpeed` โดยรวมได้มากกว่าก่อน

## 4. ความกว้างเส้นดำสนาม = 3.5 cm

ใช้กำหนดระยะห่างเซนเซอร์ (pitch) ทางกลไก แนะนำห่างกันประมาณ 1.5-2 cm ต่อชุด (array รวมกว้าง 6-8 cm) เพื่อให้มี 1-2 เซนเซอร์เหยียบเส้นตลอดตอนอยู่กลางเส้น และเห็น error ก่อนหลุดเส้นเต็มตัว ถ้า pitch ห่างกว่าความกว้างเส้น เสี่ยงเส้นตกอยู่ระหว่างเซนเซอร์สองตัวโดยไม่มีตัวไหนจับได้ ไม่ได้แก้ค่านี้ในโค้ด (`WEIGHTS` เป็นหน่วยสมมติ ไม่ผูกกับ cm จริง)

## 5. รีวิวโค้ดและแก้ไข

พบและแก้แล้ว:
1. **เส้นหลุดแล้ว error เคยแข็งตัว (freeze)** — D-term กลายเป็น 0 ตอนเส้นหลุด แก้เป็นให้ error โตขึ้นเรื่อยๆ ตามเวลาที่หลุด (`LOST_LINE_ERROR_GROWTH_PER_MS`, เพดานที่ `LOST_LINE_ERROR_MAX`) เพื่อเลี้ยวหาเส้นแรงขึ้นตามเวลา
2. **ไม่มี timeout ป้องกันหลุดสนามถาวร** — เพิ่ม `LINE_LOST_STOP_MS` (ค่าเริ่มต้น 1000ms) หลุดเส้นนานเกินนี้หยุดมอเตอร์ทันทีเสมอ ไม่ว่า `HOLD_LAST_ERROR_ON_LOST_LINE` ตั้งไว้อย่างไร
3. **Weighted average หาร integer หยาบ** — เปลี่ยนเป็น float แล้วค่อย round ตอนคืนค่า ลดการกระโดดของ error

ยังไม่ยืนยัน (รอฮาร์ดแวร์จริง):
- ทิศทางมอเตอร์ซ้าย/ขวาจริงตรงกับ `setMotor()` หรือไม่ (ต้องเทียบตามแผนข้อ 10)
- ขาเซนเซอร์จริง / HIGH-LOW ตอนเจอเส้นดำ

## 6. โครงสร้างค่าที่ปรับได้ในโค้ด (ทั้งหมดอยู่บรรทัดต้นไฟล์)

- `TEST_MODE` — เลือกโหมดทดสอบ
- ขา L298N + `INVERT_LEFT/RIGHT`
- ขาเซนเซอร์ `SENSOR_PINS[5]`, `BLACK_IS_HIGH`
- `WEIGHTS[5]`, `SETPOINT`
- `BaseSpeed`, `Kp`, `Kd`, `PWM_MIN/MAX`
- `CURVE_SLOWDOWN_ENABLE`, `MIN_CURVE_SPEED`, `MAX_ERROR_FOR_SCALE`
- `HOLD_LAST_ERROR_ON_LOST_LINE`, `LINE_LOST_STOP_MS`, `LOST_LINE_ERROR_GROWTH_PER_MS`, `LOST_LINE_ERROR_MAX`
- `DEBUG`, `DEBUG_INTERVAL_MS`

## 7. งานที่เหลือ

- ทดสอบจริงบนฮาร์ดแวร์ตามลำดับขั้นตอนในแผนข้อ 8
- ยืนยันขาเซนเซอร์/ทิศมอเตอร์จริง (แผนข้อ 10)
- ปรับระยะเซนเซอร์ทางกลไกให้เข้ากับเส้น 3.5 cm และเพิ่ม look-ahead distance สำหรับความเร็วสูง
- Tune `Kp`/`Kd`/`BaseSpeed` จากการวิ่งจริง
